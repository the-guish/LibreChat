# PostgreSQL port: plan and status

Living document for the `feature/postgres` branch of `the-guish/LibreChat`. Update it in the PR that changes the status of a phase.

## Goal

Make LibreChat able to run on PostgreSQL instead of MongoDB, switching the whole database at once, without changing caller behavior. Every database access goes through database-neutral ports; MongoDB and PostgreSQL are two adapters behind them.

## Decisions

| Decision                          | Choice                                                                                                                                                                                                                                                                                                                                                  |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Scope                             | The whole data layer behind ports (not only conversations).                                                                                                                                                                                                                                                                                             |
| Switch                            | All or nothing: the backend is chosen once for the whole database, never per module. An adapter may therefore read any table or collection it needs; callers and database-neutral code only see ports.                                                                                                                                                  |
| Branching                         | One branch per unit from `feature/postgres`, one PR per unit into `feature/postgres`, squash-merged. Always in the fork `the-guish/LibreChat`.                                                                                                                                                                                                          |
| Callers                           | Public method signatures and call sites stay unchanged wherever possible.                                                                                                                                                                                                                                                                               |
| Tests                             | Do not edit existing tests. When an edit is unavoidable, it goes in its own small test-only PR, never mixed with large code changes. The only standing exception is the port conformance specs this refactor creates (`packages/data-schemas/src/ports/*.spec.ts`): their `EXCLUDED` lists and conformance assertion may change together with the port. |
| Raw MongoDB filters in signatures | Expressed with a portable store query language (`ports/query.ts`), a typed subset of MongoDB query syntax that callers already use, rather than rewriting ~300 call sites into named methods. Hot paths can later be replaced by named methods incrementally.                                                                                           |

## Architecture

```text
packages/data-schemas/src/
├── ports/
│   ├── <module>.ts          # one port per module (XStore), no mongoose imports
│   ├── <module>.spec.ts     # conformance: MongoDB methods satisfy the port; every method placed or excluded
│   ├── common.ts            # IdLike, WithIdLike, DeleteCount, StoreTransaction, listPortMethods
│   ├── storeTransactions.ts # StoreTransactions: DataStore.transactions.transaction(fn), runAfterCommit(tx, fn)
│   ├── connection.ts        # DataStoreBackend (registerModels, createMethods, createConnection, getSearchIndexSync, createStartupChecks, getCredentialMarkerStore, createKeyValueStore, getCheckpointStore, ids, documents, errors) + DataStoreConnection (connect/close/getState/isConnected/health)
│   ├── searchIndexSync.ts   # SearchIndexSync: the database side of the search index sync (progress, sync, cleanup, flag reset)
│   ├── startupChecks.ts     # DataStoreStartupChecks: boot-time migration dry runs (search tokens, agent/prompt permissions)
│   ├── credentialMarker.ts  # CredentialMarkerStore: the credential fingerprint marker checked at boot
│   ├── keyValueStore.ts     # KeyValueStore: the infrastructure key-value cache in the main database (Keyv's store)
│   ├── storeIds.ts          # StoreIds: the id format (isValid, toCanonicalString, toStoreId, generate)
│   ├── storeDocuments.ts    # StoreDocuments: the size limit of one stored record (maxDocumentBytes, measureDocument)
│   ├── storeErrors.ts       # StoreErrors (isDuplicateKey, duplicateKeyFields) + StoreDuplicateKeyError, the neutral duplicate-key error
│   ├── conformance.ts       # SameSignatures, Satisfies, EveryMethodPlaced, ExclusionsHold (types only)
│   ├── query.ts             # StoreFilter/Projection/Sort/QueryOptions/Update + validator + reference evaluator
│   ├── query.corpus.ts      # database-agnostic differential corpus (302 cases)
│   └── index.ts             # DataStore (one store per module) + DATA_STORE_METHODS
├── compose/                 # database-neutral composition root, shared by every backend (no driver imports, lint-enforced)
│   ├── methods.ts           # composeDataMethods(factories, deps): builds each module once, wires them, returns the flat methods + stores
│   ├── stores.ts            # createDataStore(instances) (pickStore per DATA_STORE_METHODS), pickStore
│   └── types.ts             # DataModuleFactories<M> (ids + one factory per module, explicit deps), DataModules, DataMethods, CreateMethodsDeps
├── adapters/
│   ├── backend.ts           # getDataStoreBackend(): the one place the database is chosen (MongoDB today); StoreIdValue, its id type
│   └── storeErrors.ts       # isDuplicateKeyError(error), duplicateKeyFields(error) on the backend's errors
├── adapters/mongo/
│   ├── factories.ts         # createMongoDataModuleFactories(mongoose): each module's methods on mongoose (MongoDataModules)
│   ├── pickStore.ts         # re-exports pickStore from compose/stores.ts
│   ├── storeTransactions.ts # transaction(fn) on a MongoDB session (getTransactionSupport fallback)
│   ├── backend.ts           # createMongoDataStoreBackend(mongoose): createModels, createMethods, connection
│   ├── connection.ts        # MONGO_* settings, global.mongoose cache, strictQuery, query metrics patch
│   ├── searchIndexSync.ts   # mongoMeili statics per model + batchResetMeiliFlags (_meiliIndex flags)
│   ├── startupChecks.ts     # permission migration dry runs, search token probe
│   ├── credentialMarker.ts  # librechatCredentialMetadata `primary` document, User.exists
│   ├── keyValueStore.ts     # one document per key (key + expiresAt TTL indexes) or GridFS files
│   ├── storeIds.ts          # ObjectIds: Types.ObjectId.isValid, new Types.ObjectId(value), new Types.ObjectId()
│   ├── storeDocuments.ts    # 16 MiB BSON document limit, BSON.calculateObjectSize with `_id` and `__v`
│   ├── storeErrors.ts       # duplicate key: code 11000 (or 'E11000') or StoreDuplicateKeyError; fields from `keyValue`
│   ├── collections.ts       # ensureRequiredCollectionsExist (also used by the config/migrate-* scripts)
│   └── dataStore.ts         # createMongoDataStore(instances) = createDataStore(instances)
└── methods/
    ├── index.ts             # createMethods(mongoose, deps) = composeDataMethods(createMongoDataModuleFactories(mongoose), deps)
    ├── saveConvo.ts         # database-neutral domain functions built on port steps,
    ├── deleteConvos.ts      #   keeping the public signature (pattern for methods whose
    ├── bulkSaveConvos.ts    #   bodies are mostly rules rather than storage)
    └── searchConversation.ts
api/db/connect.js            # connectDb(): the backend's connection (query metrics observer from @librechat/api)
api/models/index.js          # getDataStoreBackend().createMethods(deps); spreads every store over `~/models`
```

- **Port**: the module's operations with neutral types: plain values, `IdLike` for ids, `Store*` query types for filters/projections/sorts/updates, neutral result shapes (`DeleteCount`, …).
- **MongoDB adapter**: today's methods, unchanged, picked from the same instance (instances hold state).
- **Domain functions**: logic that must be identical on every backend (`saveConvo`, `deleteConvos`, …) is written once without mongoose and built on port steps plus injected dependencies.
- **Query language** (`ports/query.ts`): filters (equality, dotted paths, array-contains, `$in`, `$nin`, `$ne`, `$exists`, `$gt`/`$gte`/`$lt`/`$lte`, `$regex` with optional `i`, `$or`, `$and`), projections (`'a b'`, `'-a'`, `'+hidden'`, `{a: 0|1}`), sorts (`{a: 1|-1}`), `limit`/`offset`, updates (plain fields, `$set`, `$unset`, `$inc`, `$max`, `$min`, `$push`, `$pull`, `$pullAll`, `$addToSet`, `$setOnInsert`). Excluded on purpose: aggregation pipelines, `$elemMatch`, `$where`/`$expr`, `$text`, positional paths, sessions. The reference evaluator defines the semantics (including MongoDB corner cases such as `null` matching a missing field) and agrees with MongoDB on all 302 corpus cases; the PostgreSQL translator will be tested against the same corpus.

### MongoDB behavior the contract suites pin

The contract suites pin these MongoDB behaviors as they are today, each marked `NOTE(contract)` in its suite. They look like bugs and are candidates for separate MongoDB fix PRs; the PostgreSQL stores reproduce them so both backends pass the same suites, and a fix changes the suite and both backends together.

1. `setMemory` and `createMemory` skip validators (`setMemoryById` validates).
2. `deletePluginAuth` without `all` ignores `pluginKey`.
3. An audit purge of every entry restarts the hash chain at genesis.
4. `roles.updateAccessPermissions`: the `$unset` of a legacy top-level permission is stripped by the strict model, so the value comes back.
5. `userGroups.upsertGroupByExternalId`: concurrent calls can fail with a duplicate key (the filter misses the unique index).
6. Renaming a tag on a conversation that carries it twice keeps the old name once.
7. `updateTagsForConversation` gives a new tag position 0.
8. Shared links are live references to the conversation, not snapshots.
9. `storeAgentEventActorSuspension`: on the first suspension, the query's `$or` overwrites the one that excludes expired threads, so the write can land on an expired thread.
10. `getConvoFiles` is not scoped to the user.
11. `getConvosQueried` pages on `updatedAt` alone, so conversations tied on `updatedAt` at a page boundary are skipped.
12. `getCodeGeneratedFiles`, `getUserCodeFiles` and `getDeferredProvisionFiles` are documented as oldest first, but return newest first: `getFiles` sorts on `updatedAt` descending before the given key.
13. `deleteAgent` without a tenant prunes agent edges and favorites in every tenant.
14. An agent update made only of operators records a version with the state from before the operators.
15. An agent update whose operators change nothing still records a version.
16. The first update after `createAgent` always records a version, since the initial version lacks the schema defaults.
17. `updatePromptGroup` skips validators, so an invalid `command` is stored.
18. `updatePromptLabels` reports success but stores nothing: the prompt schema declares no `labels`.
19. `upsertSkillFile`: a replacement that gives no storage key or region keeps the old blob location, so a later replacement queues the wrong key for cleanup (real data damage).
20. `deleteSkill` writes an upper-case id into the `__deleted__` placeholder name.
21. `iterateSkillCleanupFiles` and `iterateSkillCleanupIntents`: a `TypeError` from the `finally` block masks the invalid batch size error.
22. `listAbandonedSkillUploadIntents` does not honor its `createdAt` tie-break under the merged `$or` plan.
23. `createMCPServer` picks new names only from stored names, so a stored name that normalizes to the slug (`my-server ` to `my-server`) makes every retry pick the same name, and the create fails with a duplicate key.
24. `getListMCPServersByIds` with `limit: 0` returns the default page of 20 (`parseInt('0') || 20`), although the port clamps the limit to 1..100.
25. `reserveSetupEnvironment`: concurrent calls with the same binding can fail with "binding is unavailable", since the live reservation and the collisions are read separately.

## MongoDB-only legacy scripts

These scripts stay MongoDB only (decision for U9). Each one transforms data or indexes that exist only in a deployment that ran on MongoDB before the change it migrates, so it runs against that existing MongoDB deployment; a PostgreSQL deployment starts from the current schema (Phase 4 migrations) and never needs them, and a deployment moving from MongoDB to PostgreSQL runs any it still needs on MongoDB before moving its data. They reach MongoDB directly and are not part of the database-neutral data layer; each file starts with a header saying so. Those that import the driver (all but `migrate-code-file-duplicates` and `migrate-orphaned-agent-files`, which reach it through `api/db/models.js`) are exempt from the `data-layer/no-database-driver` lint rule by name (U10).

## Open items and known leaks

Contracts a PostgreSQL adapter must honor, or caller changes still needed:

- `CLIENT_MESSAGE_SELECT` (in `ports/message.ts`) excludes nested paths, outside the query language; a non-MongoDB store must recognize it by value.
- Duplicate keys: a PostgreSQL adapter turns a unique violation (SQLSTATE 23505) into a `StoreDuplicateKeyError` with the violated key's `keyValue` (or recognizes the driver's error in its `StoreErrors`); a skill's duplicate name keeps the message `A skill with name "…" already exists`, which the skill authoring tool also matches.
- Some reads match ids inside aggregations without casting (`getAgentWithVersionCount`, `getListAgentsByAccess` in the author sort, `getAgentManagementListByAccess`); ACL `principalId` is stored untyped and matched exactly as given. Callers must pass ids as the store returned them.
- A string queued-turn `user` must be lowercase hex (the lane key hashes `user.toString()`); a code environment's `createdBy` must be an ObjectId (an owner-slot id is derived from it).
- Ids compare as their lowercase hex string; strings compare by code point (a PostgreSQL translator needs "C" collation).
- Record types still extending mongoose's `Document` or carrying `ObjectId` fields (`IUser`, `IConversation`, `IMessage`, `IAgent`, `IMongoFile`, …): compile-time leaks only, documented in each port header.
- Some `getMessages` calls filter without `user` (`api/server/middleware/error.js`, `api/server/controllers/agents/resume.js` ×2): allowed, but relevant for future user/tenant scoping.
- `listResourcePermissionPrincipals` and `listUserPermissionHolders` (like the `aggregateAclEntries` pipelines they restate) return the joined user and group records whole, hidden fields included and from any tenant; their callers pick the fields they show and check the tenant. Narrowing the joined fields would change the rows, so it waits for the callers' switch.
- Hydrated message search (`searchUserMessages` with `hydrate`, like `searchMessages`) reads the stored fields by `messageId` alone in the MongoDB adapter (MeiliSearch's primary key), so two users' messages sharing a `messageId` can mix; a PostgreSQL store hydrates by user and `messageId`. The MeiliSearch index holds no tenant: search is scoped by user only.
- The browser setup and fence retry stores keep their consumers' short method names (`createStore`, `ensureRegistration`, `getUser`, `isConnected`; `upsert`, `deleteVersion`, `deferVersion`, `list`), which therefore also appear on the flat `~/models` export; callers should reach them through `stores.browserSetup` / `stores.mcpAuthorizationFenceRetries`. `isConnected` belongs with the `DataStore` lifecycle (`DataStoreConnection.isConnected`, phase 3 U1); the browser setup store keeps its own until its consumer moves. `createCodeEnvironmentRegistry` in `packages/api` takes the caller's data methods (phase 3, U5).
- `StoreIdValue` (the backend's id type, an ObjectId with MongoDB) still states the MongoDB id in the types of the `packages/api` files listed under U10: a PostgreSQL backend hands out ids that serve the same uses, or those dependency types move to `IdLike` together with their store methods' parameters.
- Optional test-only change: a narrowing cast in `packages/api/src/images/authorization.spec.ts` would let `images/authorization.ts` be typed against `AgentStore` (its agent lookup takes `getAgent`'s own parameter types today).
